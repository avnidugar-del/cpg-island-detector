# CpG Island Detector

![Python](https://img.shields.io/badge/python-3.8%2B-blue)
![Dependencies](https://img.shields.io/badge/dependencies-none-brightgreen)
![Tests](https://img.shields.io/badge/tests-77%20%2B%2029%20passing-brightgreen)

Two dependency-free Python implementations of a threshold-based **CpG island detector**, with full scientific write-ups, test suites, reproducible sample data, and a cross-validation of one against the other. Both scan DNA with the classical Gardiner-Garden & Frommer (1987) criteria (length, GC content, observed/expected CpG) using a sliding window, merging and a final re-check.

> **Scientific honesty.** Everything here produces *computationally predicted candidate regions* from sequence composition only. They are **not** experimentally confirmed CpG islands, and they say nothing by themselves about promoter function, methylation status, gene expression or disease. All sample data are simulated or constructed. **Neither program has been benchmarked on real genomes or against an established tool.**

## 3. The biology in 60 seconds

* **CpG** means a cytosine immediately followed by a guanine on *one strand* (5'→3'). The "p" is the phosphate linking them, which distinguishes it from a C·G base pair across the two strands. CG is its own reverse complement, so a CpG site exists on both strands.
* In bulk vertebrate DNA, CpG is **depleted**. Methylated cytosine (5mC) can deaminate to thymine, so CpGs are gradually lost as C→T changes.
* **CpG islands** are short, GC-rich stretches that retain CpGs and are generally unmethylated. A large share of vertebrate gene promoters lie in or near them.
* Promoter-island methylation is generally linked to stable silencing (X-inactivation, imprinting), and aberrant methylation is studied in cancer.

**Why three criteria and not just "lots of CG"?** GC content separates GC-rich from AT-rich DNA. Obs/Exp separates a true island from a merely GC-rich region where CpG is still depleted. Length keeps the statistics meaningful and excludes very short CpG-rich fragments. The sample data contain one record for each failure mode (see [Results](#8-results)).

## 4. The maths

For a region with **L** unambiguous bases, *c* and *g* the counts of C and G, and *n<sub>CpG</sub>* the number of positions where a C is followed by a G:

| Metric | Formula |
|---|---|
| GC content | `(c + g) / L` (shown as a percentage by A, as a fraction by B's options) |
| Expected CpG | `L · (c/L) · (g/L) = c·g / L` |
| Obs/Exp CpG | `n_CpG × L / (c × g)` |

**Worked example** (from B's report): `ACGCGTTCGA` has L = 10, c = 3, g = 3, CpG = 3 (at positions 2-3, 4-5, 8-9), so GC = 0.60, expected = 0.9, and Obs/Exp = **3.333**. In `CGCGCG` the CpGs overlap by one base but are still counted separately, giving 3.

**Classical criteria.** Gardiner-Garden & Frommer (1987): length ≥ 200 bp, GC > 50 %, Obs/Exp > 0.6. Takai & Jones (2002) proposed stricter values for human chromosomes 21 and 22: ≥ 500 bp, GC ≥ 55 %, Obs/Exp ≥ 0.65. These thresholds are conventions, not biological constants, and the original expected-CpG term is worded differently in different descriptions (B's report flags this to verify against the source paper).

**Approximations.** Both programs use `L` rather than `L − 1` adjacent positions (about a 0.5 % difference at 200 bp), assume independent neighbouring bases, and exclude ambiguous bases (N, R, Y ...) from the denominators; no CpG can span an ambiguous base.

## 5. The algorithm

```mermaid
flowchart LR
    A[FASTA input] --> B[Validate<br/>IUPAC letters, mixed case OK]
    B --> C[Prefix counts<br/>A, C, G, T, CpG]
    C --> D["Score each window in O(1)<br/>width W, step S"]
    D --> E[Keep windows passing<br/>GC, Obs/Exp, ambiguity]
    E --> F[Merge overlapping<br/>or touching windows]
    F --> G["Trim terminal non-C/G bases<br/>(Implementation B only)"]
    G --> H[Re-measure whole region<br/>and re-check ALL criteria]
    H --> I[Report and export]
```

1. **Prefix counts** make every window metric constant-time, so the whole scan is O(n) time and O(n) memory. A CpG that straddles a window boundary is counted in neither window.
2. **Sliding window.** The default window is 200 bp (the minimum island length), so one passing window is itself a valid-length island.
3. **Merge.** Windows that overlap or touch are merged. A short low-GC gap can therefore be bridged if windows spanning it still pass.
4. **Re-check.** Each merged region is measured as a whole and kept only if it still meets every criterion, because a union of passing windows does not automatically pass.
5. **Boundaries are approximate.** A window passes if the island supplies most of it, so merged regions overhang the true edge by up to about one window. A leaves this overhang visible. B trims terminal non-C/G bases, which helps but cannot remove overhang that contains scattered C and G.

Fixed windows were chosen over region growing or HMM segmentation because they are simple, deterministic, linear-time and easy to test by hand. Both reports discuss the alternatives (region growing, HMMs, distance-based clustering, experimental definitions) and why their outputs are not interchangeable.

## 6. Two implementations, side by side

These are the differences that change what you see in the output.

| Setting or behaviour | Implementation A | Implementation B |
|---|---|---|
| GC and Obs/Exp thresholds | strict (`>`) | inclusive (`>=`) with a 1e-9 tolerance |
| Obs/Exp when there is no C or no G | `NA`, never passes | defined as 0, fails |
| Default step | 10 bp | 1 bp |
| Max ambiguous fraction | 0.05 | 0.10 |
| Boundary trimming | none (overhang is documented) | on by default, `--no-trim` to disable |
| Presets | none; pass Takai-Jones values as flags | `--preset gardiner-garden` or `takai-jones` |
| GC option units | percent (`--min-gc 50`) | fraction (`--min-gc 0.5`) |
| Exit codes | 0 success, 1 input/runtime error, 2 bad usage | 0 success, 2 bad input |
| Coordinates | 1-based, inclusive | TSV/JSON 1-based inclusive, **BED 0-based half-open** |
| Plots | dependency-free SVG per sequence | none |
| Extra outputs | CSV, JSON | TSV, BED, JSON |

Because of these defaults, running both with no options is **not** a like-for-like comparison. [Section 9](#9-cross-validation) matches the step size.

## 7. Quick start

Requires **Python 3.8+** and nothing else. Both were developed and run on Python 3.12.3 (Linux); 3.8-3.11 and macOS were not executed.

```bash
git clone <your-repo-url>
cd cpg-island-detector

# Implementation A: tests, then detect + CSV + SVG plots
(cd implementation-a && python -m unittest discover -s tests -v)
python implementation-a/src/cpg_detector.py -f implementation-a/data/sample.fasta \
    -o implementation-a/results/regions.csv --plot-dir implementation-a/results/plots

# Implementation B: tests, then detect + TSV/BED/JSON
(cd implementation-b && python -m unittest discover -s tests -v)
python implementation-b/cpg_detector.py implementation-b/data/demo.fasta \
    --tsv out.tsv --bed out.bed --json out.json
```

Stricter, Takai-Jones-style criteria:

```bash
python implementation-a/src/cpg_detector.py -f my.fasta --min-length 500 --min-gc 55 --min-obs-exp 0.65 --window-size 500
python implementation-b/cpg_detector.py my.fasta --preset takai-jones
```

See each implementation's own README for every option and exit code.

| Record (B's demo) | Designed island(s) | A (default) | A (`--step-size 1`) | B (default) |
|---|---|---|---|---|
| `demo1` | 101-500 | 51-550 | 44-555 | 101-498 |

**Reading this honestly.** The two programs make the same decisions on every record except the N-gap one: A splits it into two regions and B reports one, which is consistent with B's more permissive ambiguity limit but has not been isolated as the cause. A's untrimmed boundaries overhang the designed edges, while B's trimming brings them close. All data are simulated or constructed from the same compositional ideas the detectors use, so this shows the two independent implementations behave consistently. It does **not** measure accuracy on real genomes.

## 10. Validation and testing

* **Implementation A: 77 `unittest` tests** with hand-calculated expected values, a cross-check of the O(1) prefix-count metrics against direct counting on a 600-bp pseudo-random sequence containing N, and a mutation check (four injected bugs, all caught).
* **Implementation B: 29 tests** (unit, functional and boundary), a prefix-sum check against the simple loop-based metrics on 500 random intervals, and a quality audit ([`implementation-b/docs/audit.md`](implementation-b/docs/audit.md)) that records flaws found and fixed during development: window overhang (fixed by adding trimming), a length filter that could never fire when window = minimum length, and CRLF line endings in TSV output.
* **Re-run for this repository:** both suites passed (77 and 29 tests) on Python 3.12.3.
* **What was not executed:** Python 3.8-3.11, macOS, real genomic data, any comparison with an established tool such as EMBOSS cpgplot.

## 12. Limitations and future work

**Limitations shared by both.** Results depend on thresholds that are historical conventions tuned to human-like genomes. Fixed windows bias boundaries. Only the forward strand is analysed (counts are identical on both strands, but gene context is not considered). There is no repeat masking, so CpG-rich repeats such as Alu elements can pass. The expected-CpG model is the simple `c·g/L` form and is unstable when C or G is rare. Sequences are held in memory, so whole chromosomes are not practical as written (about 20 bytes per base for A's arrays; B's report estimates over 100 bytes per base for Python lists and calls that figure unverified).

**Future work, combining the two reports.**

| Improvement | Benefit |
|---|---|
| Benchmark both against a trusted CpG-island annotation and EMBOSS cpgplot on real sequence | the first evidence-based statement about accuracy (B's audit ranks this highest-value) |
| Merge the two codebases into one tool | A's strict validation and SVG plots with B's presets, trimming and BED output |
| Boundary refinement or a two-state HMM | less overhang |
| Soft-masked input as a repeat filter | removes a known false-positive source |
| Gap-bridging option for N runs | resolves the one disagreement seen in cross-validation |
| Overlap with gene annotation (BED/GFF) | relate regions to promoters |
| Chunked or streaming scan, `array`/NumPy storage | whole-chromosome use |
| Permutation or Markov-model null for Obs/Exp | significance for small windows |
